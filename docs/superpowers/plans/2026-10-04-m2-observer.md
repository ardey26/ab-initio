**Goal:** A separate `abi-observer` program that reads a run directory's checkpoints, replays short traced slices, detects lineages, settlements, material and signal conventions, writes a factual chronicle with signal-derived names, ranks attention, and detects recurrence, so that a 60k-tick seed 6 run yields a readable chronicle unattended.

**Architecture:** One new crate `abi-observer` (lib + bin) depending on `abi-core` read-only. Per checkpoint: load, replay `slice` ticks with `step_traced`, run detectors against persisted observer state, append entries. All detectors are pure functions of (checkpoint world, trace, state) returning (entries, new state), so each is unit-testable on synthetic inputs. The chronicle is append-only JSON lines with templated past-tense facts and a denylist of evaluative words enforced by test.

**Tech Stack:** Rust stable, `abi-core`, serde, serde_json, bincode 1.x, clap 4, rayon.

**Spec:** `docs/superpowers/specs/2026-10-04-m2-observer-design.md` (binding), parent spec section 7.

## Global Constraints

- The observer never writes into `abi-core` state or the run directory except under `chronicle/`.
- Material ids never appear in chronicle text; materials are rendered from properties or by a lineage's signal name.
- No evaluative words in any fact template (denylist in spec section 6, test-enforced).
- Running the observer twice over the same run directory appends nothing the second time, and `entries.jsonl` is byte-identical across thread counts.
- All thresholds live in `thresholds.rs` with the spec's values: `LINEAGE_MIN = 20`, `SPLIT_DISTANCE = 0.35`, `EPS = 3`, `MIN_PTS = 12`, `SETTLEMENT_PERSIST = 3`, `CONVENTION_MIN_COUNT = 30`, `CONVENTION_LIFT = 4.0`, `SIGNAL_MI = 0.5`, `SIGNAL_MIN_COUNT = 50`, `ATTENTION_N = 5`, `RECURRENCE_AFTER = 5`, `RECURRENCE_SIM = 0.8`, `ERA_TICKS = 1_000_000`, `ERA_MAX_ENTRIES = 10_000`, `DEFAULT_SLICE = 200`.
- Observer budget: per checkpoint at 256x256 / 20k agents, under the sim's checkpoint interval; state file under 50 MB.
- Code contains no nouns for emergent things beyond the observer's own vocabulary, which is allowed to name patterns it detects (lineage, settlement, convention, name) because the observer is outside the causal loop.

## Review Focus

1. A run directory with a single checkpoint (tick 0 only): the observer must produce no lineage entries (populations are founders, every founder group has size 1) and no errors. Test in Task 1.
2. A checkpoint whose slice replay crosses an external event: trace replay must apply the event (the checkpoint carries the log) and the observer must not double-apply it. Test in Task 1.
3. Two founder groups whose genomes converge (identical weights): split detection must not fire, and settlement matching must not merge them into one lineage. Test in Task 3.
4. An extinct lineage whose members appear in the memory of a living agent: the last-witness entry must NOT be written. Test in Task 3.
5. Signal MI on a lineage with fewer than `SIGNAL_MIN_COUNT` emissions must never create a name even if MI is high by chance. Test in Task 6.

### Task 3: Lineages, last witness, splits

**Files:**
- Create: `src/lineage.rs`

**Interfaces:**
- `lineage::observe(world: &World, tick: u64, state: &mut ObserverState, out: &mut Vec<Entry>, next_id: &mut u64)`.
- Steps inside: group living agents by `founder` into `BTreeMap<u64, Vec<&Agent>>`; for each group size >= `LINEAGE_MIN` ensure a `LineageRecord` (birth entry when created, Scale::Lineage, subjects [Lineage]); update pops; decline entry once when `pop < pop_max / 4` and `!declined`; for each known lineage absent now (pop 0) with `ended == None`: end entry (last member = max id in `member_ids_recent`), set `ended`, store `Signature` into `extinct` (usage from `state`'s last convention tables for that lineage; zeros if none), then last-witness check: scan every living agent's `memory.slots` for any id in `member_ids_recent`; if none found, append the last-witness entry (Scale::World).
- Split detection (`fn detect_split(group: &[&Agent]) -> Option<(Vec<u64>, Vec<u64>, f32)>`): dequantize genomes of up to 2,000 sampled agents (sample = every k-th by id) that share the same `hidden`; k-means k=2 (10 iterations, deterministic init: the two agents with max and min genome hash), distance = fraction of weights differing by more than one quantization step; return the two member-id sets and the centroid distance. A split is recorded when both sets >= `LINEAGE_MIN` and distance >= `SPLIT_DISTANCE` for three consecutive observed checkpoints (track candidate count in `LineageRecord.split_candidate: u8`). The smaller set becomes `LineageKey { founder, split: next }` with `centroid`; members are assigned by nearest centroid in later checkpoints.

### Task 6: Signal conventions and naming

**Files:**
- Create: `src/signal.rs`

**Interfaces:**
- `signal::symbol(v: f32, v2: f32) -> u8` (0..16): each component quantized to 4 levels over [-1, 1].
- `signal::syllable(sym: u8) -> &'static str`: consonant by `sym / 4` from `[k, t, m, r]`, vowel by `sym % 4` from `[a, i, o, u]`.
- `signal::mutual_information(joint: &[[u32; 16]]) -> f32`: plug-in MI in bits over a `targets x 16` count matrix, minus the Miller-Madow correction `(k-1)(l-1)/(2 N ln 2)` where k and l count non-empty rows and columns; never below 0.
- `signal::observe(world, slice, lineage_of, state, out, next_id)`: per lineage, from Emit events: targets are (a) context bits as 16 classes, (b) the emitter's next traced action kind within 5 ticks (10 classes, or none), (c) held0 bin key (classes = bins seen); compute MI for each target family; if the best MI >= `SIGNAL_MI` with >= `SIGNAL_MIN_COUNT` emissions and the same (symbol, target class) leads as in the previous slice (`LineageRecord.last_signal_lead: Option<(u8, u8, u16)>`), emit a signal-convention entry. For target family (c), also record the name: `state.names[(lineage, bin)] = syllable(sym)` (two-syllable names when the emitter emitted a second symbol within 5 ticks in >= 60% of cases: concatenate) and emit the naming entry once per (lineage, bin).
- Names are consumed by `style` through a `Namer` trait object passed to `render_material` callers: `fn name_for(&self, lineage: &LineageKey, bin: &[u8;8]) -> Option<&str>`.
